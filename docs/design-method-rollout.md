# Human-shaped designs

This change requires `20261019000000_design_method.sql` before deploying the
app. Apply migrations in order with the Supabase CLI, then merge the PR.
The migration marks all existing designs `human-shaped`, as requested by the
site owner. It removes the temporary default so future inserts must provide
`human-shaped` or `generated`; a check constraint rejects other values.

Upload and edit both require a fresh choice, even if a design already has a
stored value. Both client and server validate it. Owners save the value through
their normal Supabase client and existing row-level security. The new column
has an explicit authenticated update grant; other design permissions are unchanged.

Human-shaped cards show **HS**, explained as creator-reported. Generated cards
have no badge. The design-method filter sits above hold types. Test fixtures are marked
human-shaped too.

Database types are generated by `npm run db:types` from the migrated schema.
CI saves a `database-types` artifact so they can be regenerated without a local
Docker installation. CI runs the ownership tests against a fresh migrated stack.
